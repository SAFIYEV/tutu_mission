Обычный сервис путешествий возвращает десятки билетов и оставляет решение пользователю. **tutu mission** принимает конечную цель естественным языком, получает актуальные предложения через официальный Tutu MCP, собирает комбинации поездки и программно доказывает, что выбранный план выполним.

> «Завтра к 18:00 мне нужно быть в Санкт-Петербурге. Я в Москве. Бюджет до 15 000 ₽, без самолёта, приехать минимум за два часа и вернуться следующим утром».

Результат — не поисковая выдача, а одна рекомендация: маршрут туда и обратно, проживание при необходимости, полная цена, запас до события, объяснение выбора и независимый список проверок.

## Почему это не очередной ИИ-планировщик

Модель решает только задачи, где нужен язык: извлекает ограничения и помогает объяснить результат. Она **не может присвоить маршруту статус «проверено»**.

| Этап | Кто отвечает | Гарантия |
|---|---|---|
| Понимание запроса | Claude Sonnet 4.6 в AWS Bedrock + Zod | Ответ модели проходит строгую схему |
| Поиск предложений | официальный Tutu MCP | Сырые ответы не попадают в домен напрямую |
| Сборка и фильтрация | детерминированный TypeScript | Все обязательные условия проверяются кодом |
| Ранжирование | прозрачная scoring-функция | Цена, время, пересадки, запас и комфорт измеримы |
| Финальная верификация | независимый Mission Verifier | `VERIFIED` возникает только из набора пройденных checks |
| Невозможная задача | алгоритм минимальной релаксации | Показывает наименьшее изменение, создающее маршрут |

## Что умеет MVP

- понимает русский запрос, относительные даты и фразы вроде «через 5 дней» в контексте даты поездки;
- работает с поездами, самолётами, автобусами, электричками и отелями;
- конвертирует иностранный бюджет в рубли по актуальному курсу ЦБ РФ;
- учитывает дедлайн, запас до события, бюджет, транспорт, пересадки, длительность и возврат;
- переживает частичную недоступность транспорта, повторяет временные сбои MCP и использует короткий stale-cache только из реальных ранее полученных данных;
- отличает невозможную миссию от технического сбоя поставщика;
- автоматически применяет доказанную минимальную корректировку и запускает поиск заново;
- показывает один основной маршрут и Plan B, не превращая результат в агрегатор.

## Структура проекта

```text
src/
├── app/
│   ├── api/mission/       # HTTP-контракт, классификация ошибок, composition root
│   └── page.tsx           # вход в интерфейс
├── features/mission/
│   ├── model/             # клиентский state machine
│   └── ui/                # create / solving / result / error states
└── lib/
    ├── ai/                # Claude Bedrock adapter
    ├── currency/          # курс ЦБ РФ
    ├── mission/           # чистый домен, solver, verifier, relaxation
    └── tutu/              # MCP client и anti-corruption adapter
```

Ключевое правило зависимости проверяется тестом: `src/lib/mission/*` не импортирует AI, Tutu MCP или валютную инфраструктуру. Оркестратор зависит от портов, а не от конкретного провайдера.

## Как принимается решение

1. Запрос превращается в `MissionConstraints` и валидируется Zod.
2. Адаптер приводит ответы Tutu MCP к внутренним `TransportOption` и `HotelOption`.
3. Генератор создаёт допустимые комбинации «туда / обратно / отель».
4. Solver отбрасывает нарушения hard constraints.
5. Ranker сортирует оставшиеся варианты по явной функции стоимости.
6. Verifier независимо повторяет проверки победителя.
7. UI показывает статус выполнения только при `verification.verified === true`.

Если кандидатов нет, алгоритм проверяет одиночные и ограниченные составные релаксации: повышение бюджета, сдвиг времени, уменьшение запаса, разрешение транспорта, пересадок или снятие требования возврата. Предложение показывается только вместе с маршрутом, который после изменения успешно прошёл verifier.

## Запуск

Требования: Node.js `22.18+`, npm, доступ к Tutu MCP. Для AI-разбора — AWS Bedrock с Claude Sonnet 4.6.

```bash
git clone https://github.com/SAFIYEV/tutu_mission.git
cd tutu_mission
npm ci
cp .env.example .env.local
npm run dev
```

Откройте [http://localhost:3000](http://localhost:3000).

На Windows PowerShell вместо `cp`:

```powershell
Copy-Item .env.example .env.local
```

### AWS Bedrock

Поддерживаются два безопасных способа авторизации:

```bash
aws login
```

или Bedrock API key в локальном `.env.local`:

```dotenv
AWS_REGION=us-east-1
AWS_BEDROCK_MODEL_ID=global.anthropic.claude-sonnet-4-6
AWS_BEARER_TOKEN_BEDROCK=your-secret
```

Секреты никогда не коммитятся. При недоступном Bedrock приложение использует ограниченный детерминированный парсер и явно сообщает об источнике разбора.

## Проверка качества

```bash
npm run check              # type generation + typecheck + lint + 70 тестов + build
npm run test:bedrock-live  # реальный вызов Bedrock, требует AWS-доступ
npm run test:api-live      # smoke-тест запущенного API
```

CI повторяет полный quality gate для каждого push и pull request. Покрыты успешный маршрут, бюджет, опоздание, arrival buffer, запрещённый транспорт, пересадки, возврат, отели, scoring, impossible mission, минимальная релаксация, таймзоны, пагинация, retry/cache MCP, concurrency и API-контракт.

## Надёжность

- bounded retry с backoff и поддержкой `Retry-After`;
- timeout и abort propagation от HTTP-запроса до внешних адаптеров;
- coalescing одинаковых одновременных MCP-вызовов;
- ограниченная конкурентность поисков;
- частичные результаты через `Promise.allSettled`-семантику;
- свежий cache и `stale-if-error` без генерации вымышленных предложений;
- отдельные состояния validation / impossible / upstream unavailable;
- строгие runtime-схемы на границах системы;
- production build и архитектурные правила в CI.

## Деплой

GitHub Pages не подходит: проект использует серверный route handler, AWS Bedrock и Tutu MCP. В репозитории есть `render.yaml` для полноценного Next.js Web Service на Render. Инструкция и список секретов — в [docs/DEPLOYMENT.md](docs/DEPLOYMENT.md).

## Ограничения MVP

- покупка и бронирование остаются на стороне Туту по ссылкам из MCP;
- детский состав пассажиров требует уточнения, чтобы не выдавать неверную цену;
- поиск ограничен разумным временным окном и числом страниц MCP;
- stale-cache живёт только в памяти одного процесса;
- качество покрытия международных направлений зависит от актуальных возможностей Tutu MCP.
